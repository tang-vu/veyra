# Veyra v0.1.0

Veyra v0.1.0 is the first public, pre-1.0 release of the local reversible-execution kernel for AI
agents. It provides one shared protocol and security boundary across the Rust kernel, authenticated
daemon, CLI, TypeScript SDK, and Windows desktop control plane.

## Highlights

- Deny-by-default, expiring and principal-bound capabilities with content-addressed approvals.
- A SQLite WAL journal with authenticated receipts, hash-chain and durable-state verification,
  conservative recovery classification, and redacted audit export.
- Confined filesystem operations with verified rollback, bounded allowlisted HTTP, and a
  disabled-by-default direct-argv process adapter.
- Generated JSON Schemas, a typed TypeScript SDK, a custom-adapter example, and 64 adversarial
  security and recovery scenarios.
- Linux and Windows CLI/daemon archives, plus an unsigned Windows NSIS desktop installer.
- SHA-256 checksum files, GitHub/Sigstore build-provenance attestations, and an attested SPDX 2.3
  repository dependency snapshot for the release revision.

## Artifacts

- `veyra-linux-x86_64.tar.gz` — `veyra` CLI and `veyra-server` for Linux x86-64.
- `veyra-windows-x86_64.zip` — `veyra.exe` and `veyra-server.exe` for Windows x86-64.
- `Veyra_0.1.0_x64-setup.exe` — unsigned Windows desktop installer.
- `veyra-v0.1.0.spdx.json` — multi-ecosystem repository dependency snapshot generated by Anchore
  Syft 1.42.3 from the exact tagged checkout. It includes build and development dependencies and is
  not a per-binary inventory.
- `veyra-v0.1.0.release-manifest.json` — attested inventory binding every uploaded file digest to the
  exact source-tag commit and the protected release-control commit.
- Every binary archive, installer, SBOM, and release manifest has a sibling `.sha256` file.

The Rust crates and npm packages are release-ready but are not published to crates.io or npm in this
release. Use the GitHub artifacts or build from the tagged source.

## Verify the download

Download into a clean directory, verify every checksum, then verify GitHub attestations:

```sh
gh release download v0.1.0 --repo tang-vu/veyra --dir dist
cd dist
for checksum in *.sha256; do sha256sum --check "$checksum"; done
gh attestation verify ./veyra-linux-x86_64.tar.gz --repo tang-vu/veyra
gh attestation verify ./veyra-v0.1.0.spdx.json --repo tang-vu/veyra
gh attestation verify ./veyra-v0.1.0.release-manifest.json --repo tang-vu/veyra
```

On Windows, use `Get-FileHash -Algorithm SHA256` and compare it with the corresponding `.sha256`
file. The release remains immutable after publication; fixes are issued as a new patch release.

## Security and trust boundary

This is an early, local, single-daemon release—not a general sandbox or multi-user security boundary.
The bearer token is an administrative root credential for one OS account. Registered in-process
adapters are trusted code, the local audit anchor does not resist a privileged host compromise, and
unknown external crash outcomes may require manual recovery. “Reversible” applies only when an
adapter can verify restoration under its documented preconditions.

The binaries and Windows installer are unsigned at the platform level because the project does not
yet have a real signing identity; verify their GitHub provenance and checksums. A medium advisory in
Tauri's target-specific GTK3/`glib 0.18` dependency family remains visible and tracked in
[issue #4](https://github.com/tang-vu/veyra/issues/4). The supplied Linux archive contains only the
CLI and daemon, and the supplied desktop installer targets Windows, but downstream source builders
should review that issue before building a Linux desktop bundle.
